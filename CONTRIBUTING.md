# Contributing to Calcine

Thanks for helping! This document covers the branch model, commit conventions,
and local setup.

## Branches

| Branch | Purpose | Releases |
|---|---|---|
| `main` | Stable | Tagged `vX.Y.Z` releases, "Stable" update channel |
| `dev` | Integration | Automatic `-beta.N` pre-releases, "Beta" update channel |
| `feat/*`, `fix/*`, `chore/*`, `docs/*` | Work in progress | — |

- Branch off **`dev`** and open your pull request against **`dev`**.
- `main` only receives release pull requests from `dev` (and automated release commits).
- Pull requests are **squash-merged**; both protected branches keep a linear history.

## Commit and PR titles

PR titles must follow [Conventional Commits](https://www.conventionalcommits.org/)
because they become the squashed commit message and feed the changelog:

```
feat(models): add precision picker for Hugging Face GGUF repos
fix(gateway): reject requests with an unknown Origin header
chore(runtime): bump GenieX to v0.8.1
```

Common scopes: `app`, `ui`, `chat`, `models`, `discover`, `server`, `gateway`,
`hardware`, `settings`, `runtime`, `core`, `ci`, `deps`, `docs`.

## Local setup

Requirements: Windows 11 ARM64 on a Snapdragon device (for real inference),
[rustup](https://rustup.rs) (the pinned toolchain in `rust-toolchain.toml` is
installed automatically), the Visual Studio C++ build tools, and
[bun](https://bun.sh).

```bash
bun install
bun run app        # desktop app against your local GenieX install
bun run app:mock   # same UI with fake data, no GenieX or Snapdragon needed
```

Before opening a pull request:

```bash
cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
bun run lint && bun run typecheck && bun run test
```

`cargo test` also regenerates `src/lib/bindings.ts`; commit it with your change.
Tests against the real GenieX are opt-in:
`cargo test -p calcine-geniex -- --ignored`.

See [docs/architecture.md](docs/architecture.md) for the code layout.

## Adding a feature

1. Domain logic goes in `crates/calcine-core` or an adapter crate, never directly
   in a Tauri command.
2. Expose it through a thin command in `src-tauri/src/commands/`; TypeScript
   bindings are generated by tauri-specta.
3. Build the UI in `src/features/<feature>/`.
4. If it wraps a new GenieX command or flag, update `docs/cli-coverage.md`.
